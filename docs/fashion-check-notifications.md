# 时尚品鉴订阅通知

## 用户命令

- `/fc`：查询本周答案。
- `/fc follow`：订阅当前私聊，或由管理员订阅当前群的后续更新。
- `/fc unfollow`：取消当前私聊订阅，或由管理员取消当前群订阅。

群订阅仅限已授权管理员设置；订阅成功后，更新会自动发送到对应群。

## 推送规则

- 周二主题和标签发生有效变化时，推送一次本周主题。
- 周五仅在装备答案满足现有完整性校验后，推送一次完整答案；同周答案有后续有效变化时会再次推送。
- 当前周的 80 分和 100 分方案都齐全，并且经过维护者手工确认后，才会为该周建立完成锁；后续重复采集不会再次推送答案。进入下一周后自动使用新的周次锁。
- 来源失败、窗口结束仍不完整等异常只发送给管理员通过 `/fc bind` 绑定的私聊。
- 订阅者在订阅前产生的历史更新不会补发。

## 数据边界

订阅内容来自机器人私有暂存的已采集结果。该通知机制不写入网页公开 JSON，不写入插件更新 JSON，也不执行 Git 提交、推送或部署。

订阅更新最多保留最近 24 条，用于机器人重启后的断点续发。每位订阅者独立记录最后成功发送的更新；单个私聊发送失败时仅保留该用户的待发送状态，其他订阅者不受影响。

## 周二手工预览覆盖

当公开 QQ 历史源仍停留在上一周、但维护者已从游戏内确认本周主题与标签时，可以在生产私有 `current.json` 的 `manualAnswers.<国际服周次>.preview` 中填写：

- `cnIssue`、`startDate`、`theme` 和官方 `themeId`；
- `slots[]` 的 `slotId`、中文 `slotLabel` 与中文 `tag`。

采集器会按当前应有的国际服周次应用该覆盖，并把答案数和染色数保持为零。相同预览签名只产生一次主题订阅更新，不会创建周五答案完成锁。周五录入答案时继续使用同一周次下的 `answers`、`dyeGuide` 和 `scorePlans` 字段；不要直接改写 `sources.qq-cn-history`，因为下次自动采集会覆盖该字段。
